# 1. O site sem servidor

> Série: construindo um encurtador de URL serverless na AWS — [índice](README.md)

## O que é o S3

Um lugar para guardar arquivos. Você sobe um arquivo, ele fica lá, e você o
acessa por uma URL. Sem disco para dimensionar, sem servidor para manter.

## Como funciona

O S3 guarda **objetos** dentro de **buckets**. Um objeto é o arquivo mais seus
metadados; um bucket é o contêiner, e o nome dele é **único no mundo inteiro** —
não só na sua conta. Por isso todo tutorial manda botar um número no fim.

Duas coisas que confundem no começo:

**O S3 não é um sistema de arquivos.** Não existe pasta de verdade. O que
parece pasta é só a barra no nome do objeto: `assets/app.js` é um objeto cujo
nome contém uma barra. O console desenha pastinhas por conveniência.

**O S3 é regional.** O bucket vive numa região e é servido de lá. Para servir
mais perto do usuário é preciso um CDN na frente, que é outro serviço.

## Onde entra no encurtador

O S3 hospeda o frontend: o HTML, o CSS e o JavaScript que o usuário abre no
navegador. Nada mais.

É o jeito mais direto de entender serverless: um site estático não precisa de
Nginx, de Apache, de contêiner nem de máquina. Precisa de um lugar que devolva
arquivos por HTTP — e é exatamente isso que o S3 faz.

## Hands-on

### 1. Criar o bucket

Console → busque **S3** → **Create bucket**.

- **Bucket name:** `url-shortener-site-SEUNUMERO` (troque por um número qualquer)
- **AWS Region:** `us-east-1`
- Deixe o resto no padrão → **Create bucket**

> 📸 **Print:** a tela de criação com o nome preenchido, destacando o aviso de
> que o nome é globalmente único.

### 2. Liberar o acesso público

Por padrão a AWS bloqueia tudo. Entre no bucket → aba **Permissions** → seção
**Block public access (bucket settings)** → **Edit** → desmarque
**Block all public access** → marque o reconhecimento → **Save changes**.

O aviso em vermelho é esperado: estamos abrindo de propósito, porque é um site.

### 3. Subir o `index.html`

Aba **Objects** → **Upload** → **Add files** → escolha o `index.html` →
**Upload**.

### 4. Ligar o website hosting

Aba **Properties** → role até **Static website hosting** → **Edit** →
**Enable** → **Index document:** `index.html` → **Save changes**.

Anote a URL que aparece. É algo como
`http://url-shortener-site-SEUNUMERO.s3-website-us-east-1.amazonaws.com`.

> 📸 **Print:** a seção de Static website hosting já habilitada, com a URL
> visível.

### 5. Conceder leitura pública

Aba **Permissions** → **Bucket policy** → **Edit** → cole, trocando o nome:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "PublicReadGetObject",
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::url-shortener-site-SEUNUMERO/*"
  }]
}
```

**Save changes.** Agora abra a URL do passo 4.

> 📸 **Print:** o site carregado no navegador, com o formulário vazio.

## O que deu errado (e por quê)

**403 ao abrir a URL.** É o erro número um aqui, e quase sempre a causa é a
mesma: você desmarcou o Block Public Access mas não criou a policy.

São dois controles diferentes, e isso é proposital:

- O **Block Public Access** é a trava de segurança. Ele não concede nada — ele
  *impede que você conceda*.
- A **bucket policy** é a permissão em si.

Destravar não abre. É como destrancar a porta sem abri-la.

**403 mesmo com a policy.** Confira o `/*` no fim do `Resource`. Sem ele, a
policy fala sobre o *bucket*, não sobre os *objetos* dentro dele — e quem o
navegador quer ler são os objetos.

## Como isso sustenta serverless

Você acabou de pôr um site no ar e não existe servidor nenhum envolvido. Não há
sistema operacional para atualizar, processo para reiniciar, certificado para
renovar nem capacidade para dimensionar. Se amanhã mil pessoas abrirem ao mesmo
tempo, não muda nada do seu lado.

E o custo acompanha o uso: você paga pelo armazenado e pelo transferido. Um site
que ninguém visita custa praticamente zero — algo impossível num servidor, que
cobra por estar ligado.
